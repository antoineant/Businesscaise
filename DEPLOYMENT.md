# BusinessCase Render Deployment Guide

This guide will walk you through deploying the BusinessCase application to Render using the included `render.yaml` configuration file.

## Overview

The application consists of four services that will be deployed:

1. **PostgreSQL Database** - Managed PostgreSQL database
2. **Backend API** - Node.js Express server with Socket.IO
3. **Main Frontend** - Student player interface (React)
4. **GM Dashboard** - Instructor/Game Master interface (React)

## Prerequisites

- Render account with Standard tier subscription (you have this ✓)
- Git repository connected to Render
- GitHub/GitLab account

## Step-by-Step Deployment

### 1. Connect Your Repository to Render

1. Log in to your [Render Dashboard](https://dashboard.render.com/)
2. Click **"New +"** → **"Blueprint"**
3. Connect your GitHub/GitLab account if not already connected
4. Select this repository: `antoineant/Businesscaise`
5. Render will automatically detect the `render.yaml` file

### 2. Review the Blueprint

Render will show you the four services that will be created:

- ✅ `businesscase-db` (PostgreSQL) - Standard plan
- ✅ `businesscase-api` (Web Service) - Standard plan
- ✅ `businesscase-frontend` (Static Site) - Starter plan
- ✅ `businesscase-gm-dashboard` (Static Site) - Starter plan

### 3. Configure Environment Variables

Before deploying, you need to set the environment variables that are marked as `sync: false` in the render.yaml file.

#### Backend API (`businesscase-api`)

The following environment variables will be **automatically configured** by Render:
- ✅ `DATABASE_URL` - Auto-populated from database
- ✅ `DB_HOST` - Auto-populated from database
- ✅ `DB_PORT` - Auto-populated from database
- ✅ `DB_NAME` - Auto-populated from database
- ✅ `DB_USER` - Auto-populated from database
- ✅ `DB_PASSWORD` - Auto-populated from database
- ✅ `JWT_SECRET` - Auto-generated by Render

**You MUST manually set:**
- `CORS_ORIGIN` - **CRITICAL!** Set this AFTER the frontend services are deployed

**Optional (for AI features):**
- `PERPLEXITY_API_KEY` - Only if using the AI "Ask the Market" feature

#### Frontend Services

For both `businesscase-frontend` and `businesscase-gm-dashboard`, you MUST set:

- `VITE_API_URL` - Backend API URL (will be something like `https://businesscase-api.onrender.com/api`)
- `VITE_SOCKET_URL` - Backend API URL for WebSocket (same as above but without `/api`)

### 4. Deploy in the Correct Order

**Important:** Due to environment variable dependencies, deploy in this order:

1. **Deploy Database First**
   - Click "Apply" on the blueprint
   - Wait for the database to be provisioned (~2-3 minutes)
   - Note the database connection string

2. **Deploy Backend API**
   - The backend will deploy automatically after the database
   - Wait for it to complete (~5-7 minutes for initial build)
   - The build process will:
     - Install dependencies
     - Compile TypeScript
     - Run database migrations automatically
   - **Copy the backend URL** (e.g., `https://businesscase-api.onrender.com`)

3. **Configure Frontend Environment Variables**
   - Go to `businesscase-frontend` service settings
   - Set `VITE_API_URL` to `https://businesscase-api.onrender.com/api`
   - Set `VITE_SOCKET_URL` to `https://businesscase-api.onrender.com`
   - Save and trigger a redeploy

4. **Configure GM Dashboard Environment Variables**
   - Go to `businesscase-gm-dashboard` service settings
   - Set `VITE_API_URL` to `https://businesscase-api.onrender.com/api`
   - Set `VITE_SOCKET_URL` to `https://businesscase-api.onrender.com`
   - Save and trigger a redeploy

5. **Update Backend CORS Settings**
   - Go to `businesscase-api` service settings
   - Set `CORS_ORIGIN` to include both frontend URLs (comma-separated):
     ```
     https://businesscase-frontend.onrender.com,https://businesscase-gm-dashboard.onrender.com
     ```
   - Save and trigger a redeploy

### 5. Verify Deployment

Once all services are deployed:

1. **Check Backend Health**
   - Visit: `https://businesscase-api.onrender.com/health`
   - Should return: `{"status":"ok","timestamp":"...","environment":"production"}`

2. **Test Main Frontend**
   - Visit: `https://businesscase-frontend.onrender.com`
   - Should load the student player interface

3. **Test GM Dashboard**
   - Visit: `https://businesscase-gm-dashboard.onrender.com`
   - Should load the Game Master dashboard

4. **Test Database Connection**
   - Try logging in or creating an account
   - Check the backend logs for any database connection errors

## Post-Deployment Configuration

### 1. Update CORS Origins

After both frontends are deployed, update the backend's `CORS_ORIGIN` environment variable:

```bash
# Format: comma-separated URLs with NO spaces
https://businesscase-frontend.onrender.com,https://businesscase-gm-dashboard.onrender.com
```

**Important:**
- No spaces between URLs
- No trailing slashes
- Must use HTTPS
- Redeploy the backend after changing this

### 2. Database Seeding (Optional)

If you want to seed the database with initial data:

1. Connect to your backend service shell in Render
2. Run: `npm run seed`

Or use Render's built-in PostgreSQL client to execute SQL directly.

### 3. Set Up Custom Domains (Optional)

You can configure custom domains for your services:

1. Go to each service settings
2. Navigate to "Custom Domains"
3. Add your domain (e.g., `app.yourdomain.com`)
4. Follow DNS configuration instructions
5. Update `CORS_ORIGIN` to include custom domains

### 4. Enable Auto-Deploy

All services in the `render.yaml` have `autoDeploy: true`, meaning:
- Every push to your `main` branch will trigger automatic deployment
- You can disable this in individual service settings if needed

## Troubleshooting

### Frontend Shows "Network Error" or Cannot Connect to API

**Problem:** CORS errors or wrong API URL

**Solution:**
1. Check browser console for exact error
2. Verify `VITE_API_URL` and `VITE_SOCKET_URL` are set correctly in frontend service
3. Verify `CORS_ORIGIN` in backend includes the frontend URL
4. Ensure no trailing slashes in URLs
5. Check backend logs for CORS configuration on startup (look for "🔒 CORS configured for origins:")

### Backend Service Fails to Start

**Problem:** Database connection errors

**Solution:**
1. Check backend logs for specific error messages
2. Verify database service is running
3. Check that all `DB_*` environment variables are set correctly
4. Verify database migrations ran successfully during build

### Database Migration Errors

**Problem:** Migrations fail during deployment

**Solution:**
1. Check build logs for specific migration errors
2. Ensure database is accessible from backend service
3. Manually connect to database and check schema
4. Try running migrations manually: `npm run migrate:up`

### File Uploads Not Working

**Problem:** Files not persisting or upload errors

**Solution:**
1. Verify the disk is mounted at `/opt/render/project/src/uploads`
2. Check disk usage in Render dashboard
3. Ensure `UPLOAD_DIR` environment variable is set correctly
4. Check backend logs for upload-related errors

### WebSocket Connection Issues

**Problem:** Real-time features not working

**Solution:**
1. Verify `VITE_SOCKET_URL` matches backend URL exactly
2. Check that CORS is configured for Socket.IO (it is, in server.ts:36-40)
3. Ensure HTTPS is used for WebSocket connections
4. Check browser console for WebSocket connection errors
